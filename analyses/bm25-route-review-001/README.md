# BM25 作为 Agent 检索工具底层：候选覆盖与证据边界

本报告串起已完成的整段 BM25、七种词法变体、用户/助手角色加权、分别设计的 BM25/向量查询输入，以及一次 Agent 补查实验。核心问题是：**Agent 生成检索工具参数后，先展示 BM25 Top5，必要时展开同一排序的第 6–10 名，能否作为默认检索流程？**

查询词由 Agent 在原本就要发生的工具调用中生成，是产品设计中的自然步骤；它不必意味着另加一次模型请求。因此，本报告把**已设计关键词的 BM25**作为目标方案的候选覆盖主结果，原问题直接检索只作对照。但现有关键词由了解项目历史的 Codex 预先编写，不是在线 Agent 在未知题上自动生成的首分。这里没有测到它的运行时稳定性，也没有单独测量生成这些参数的增量 token 或延迟。

## 固定输入与评价方法

- 复用原 LongMemEval 25 题、后续 LongMemEval 32 题、LoCoMo 200 题，总计 257 题。LoCoMo 的 200 题仅来自 10 份历史，并非 200 份独立历史；这批题此前都已被使用过。
- 使用 [SMM-SF-LUNA001](../../experiments/smm-sufficiency-luna-001/README.md) 在其模型执行前冻结的回答依赖标注。232 题可明确判定，25 题有歧义而单列（原组 2、新组 1、LoCoMo 22）。该审核由研究作者完成，不是外部独立金标，且晚于早期检索探索。
- “至少一项”指一道题的候选满足至少一个依赖单位；“全部取齐”指满足该题全部依赖单位。某一单位可有替代来源组合，组合也可能需要多段来源。另有 296 个依赖单位的微平均。所有指标均是**来源候选覆盖**，不是最终答案正确率，也不证明模型读懂证据。
- 原文、索引、问题、可见时间及冻结排名沿用父实验。双路 Top5 合并后按对话 ID 去重，不再截断。TopN 为“最多 N 段”；改写 BM25 在少量题上不足 N 段匹配。

## 1. 现有排序器：相同原问题、相同来源

每格为“至少一项 / 全部取齐”，分母均为 232 道明确题。七种词法变体的 257 份完整来源排名在 [lexical-rankings](lexical-rankings/)；它们从先前已完成的 SMM-MC001 词法分支按原字节复制，逐文件 SHA256 在 [source-manifest.json](source-manifest.json)。原始方法源码副本、冻结协议及第一次官方参考口径汇总也封存在本目录。被用户叫停并清理的 SPLADE/ColBERT 半成品没有包含在本报告。

| 整段检索方法 | Top5 至少一项 / 全部取齐 | Top10 至少一项 / 全部取齐 |
|---|---:|---:|
| 原 BM25 | 212 / 199 | 225 / 211 |
| Porter 词干化 | 211 / 198 | 225 / 215 |
| 整段与局部 RRF | 211 / 196 | 226 / 214 |
| 查询词覆盖与邻近度 | 212 / 199 | 225 / 211 |
| BM25 长度参数 b=.25 | 214 / 199 | 225 / 213 |
| BM25 词频参数 k1=.6 | 211 / 198 | 225 / 211 |
| BM25+ | 211 / 199 | 225 / 212 |
| BM25L | 212 / 200 | 223 / 210 |

词干化把 Top10 全部取齐提高 4 题，却使 Top5 少 1 题；其余变体收益与回退也交错。按同一依赖口径，**没有一种固定 BM25 公式改动在 Top5 和 Top10 上都形成明确优势**。这是冻结已用题上的对比，不应选成绩最高的一行后当作盲测泛化能力。

[用户/助手角色加权实验](../../experiments/smm-bm25-role-weight-001/README.md)只覆盖原组和新 LongMemEval 组中的 54 道明确题；LoCoMo 两位说话人都是人类，不能硬分用户与 AI。原整段 BM25 的 Top5/Top10 全部取齐为 **48/54、50/54**；独立索引 5:5 融合为 **48/54、50/54**，7:3 融合为 **46/54、51/54**。固定加重用户文字有局部帮助，但 Top5 也有真实回退。

## 2. Agent 生成检索参数：查询输入对候选覆盖的影响

只替换查询输入，不改索引、来源或排序器。[SMM-QI001](../../experiments/smm-query-input-001/README.md)已公开 257 题的原/改写查询、完整排名、输入审核与协议。本表用同一套回答依赖重新评分；原父实验报告使用的是“全部官方参考对话”，二者不能混用。

| 候选方式 | 原问题：至少一项 / 全部取齐 | 设计后的输入：至少一项 / 全部取齐 | 改写后的依赖单位覆盖 |
|---|---:|---:|---:|
| BM25 Top5 | 212 / 199 | **218 / 211** | 263/296 |
| 向量 Top5 | 167 / 153 | 161 / 146 | 194/296 |
| BM25 Top10 | 225 / 211 | **228 / 225** | 282/296 |
| 向量 Top10 | 204 / 190 | 203 / 190 | 245/296 |
| BM25 Top5 ＋ 向量 Top5 | 220 / 208 | **225 / 217** | 273/296 |

已设计关键词的 BM25 Top5 **211/232 = 90.9%** 全部取齐；Top10 **225/232 = 97.0%**。Top5 未取齐的 21 题中，同一排序的第 6–10 名能补齐 14 题，仍有 7 题即使展开 Top10 也未取齐。改写 BM25 Top5 实际平均有 4.99 段匹配，Top10 平均 9.77 段；改写后双路各 Top5 并集平均为 7.83 段。

逐组看，BM25 Top5 → Top10 全部取齐分别为 **23→23/23、27→31/31、161→171/178**。从原问题切换为设计关键词后，BM25 Top5 全部取齐 **199→211**：18 题新增、6 题回退；BM25 Top10 **211→225**：15 题新增、1 题回退。向量语义改写并未带来总体改善。把两路改写后各取 Top5，全部取齐从 208 提到 217，但仍低于单用改写 BM25 Top10 的 225；两者输入候选数量也不同。

## 3. “Top5 先看，不够再展开 Top10”能证明到哪一步？

如果检索器第一次就计算完整 BM25 排名，只先展示前五段，那么展示第 6–10 名无需**重新搜索或生成新查询**。本批数据说明这种流程值得作为简单默认方案：在理想情况下，判断器对 14 道“可以由第 6–10 名补齐”的题全都要求展开，就可把来源取齐从 211 提至 225。另有 7 道 Top10 仍缺；仅展开固定排名无法解决。

但是 **225/232 是静态 Top10 的候选覆盖上限，不是已运行的“决策模型＋按需展开”成绩**。若判断器把可补齐的题误判为“已经足够”，实际取齐会低于 225。若它把已齐全题误判为缺失，会增加阅读/决策成本。无论判断是否准确，已有候选之外根本没有线索的隐含事件，也不能仅凭 Top5 推断“已穷尽”。

已有 Luna high 的[一次补查实验](../../experiments/smm-sufficiency-luna-001/README.md)用的是**原问题 BM25 Top5**，不是本表的设计关键词：它在 33 道明确缺失题中识别出 23 题，补查后 14 题取齐，最终 213/232；同一原问题静态 BM25 Top10 为 211/232。两者相差 2 题，但输入、候选路径和模型使用不同，不能据此证明二次搜索永远不划算，更不能把 Luna 的判断率直接移植到设计关键词或其他决策模型。

[OpenAI Decisions API 官方文档](https://developers.openai.com/api/docs/guides/decisions)说明它返回定型判断与概率，并称相对 Responses API 更快；[Jev 开发者介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)给出其服务上的低延迟示例。这些是接口能力或供应商测量，**不是对本任务充分性判断的实测**。本研究没有调用 Jev/Decisions 做这 232 题，也没有测长对话输入下的端到端延迟、误判、成本和最终回答质量；不能保证它们在“毫秒级”准确发现缺失。若要评估阈值，需在独立标注样本上分别量化漏判缺失与无谓展开；OpenAI 文档也建议按应用场景标签设阈值。

## 结论等级

**已有证据支持：**在这些已用、可明确标注的对话题上，Agent 使用设计好的关键词时，整段 BM25 是强且简单的候选检索基线。固定排名 Top10 比 Top5 多取齐 14 题；不必为了得到第 6–10 名再发起新的 BM25 查询。对当前设置，可先实现“同次排序保留 Top10、先呈现 Top5、按需展开”。

**仍是待验证假设：**在线 Agent 能稳定写出同等质量的查询参数；Jev/Decisions 能快速而可靠地识别缺失；“按需展开”能够接近静态 Top10 的 225/232；彻底取消针对性二次检索不会损失有价值的答案。当前数据更适合确定**默认路径**，不足以宣布**所有问题都无需二次搜索**。真正比较性价比时，应在未参与设计的新题、相同最多 10 段来源与相同模型读入预算下，对比静态展开和基于新查询的二次检索，同时记录最终答案、漏判、无谓展开、耗时与费用。
