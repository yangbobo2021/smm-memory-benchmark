# SMM-RG001：新问题检索验证方法

本实验检验：SMM-B001 上的 BM25 Top4 全部取齐官方参考对话，能否推广到新的问题。它是**检索方法验证**，不执行模型筛选或回答，不产生新的回答正确率。

## 检索前固定的两组数据

**LongMemEval 新题 32 道。** 固定 500 题版本中，按本地旧实验的协议、输入、评审等元数据精确匹配问题/编号，保守排除曾出现过的题，包括曾进入准备计划但未正式查询的题。剩余正例 69 道；其中 37 道的至少一段官方参考对话发生在提问之后，无法在既定时间权限下取齐，故在检索之前单独记录，不计为排序失败。其余 32 道全部纳入，使用固定种子随机排序，不根据检索表现抽换。

旧题排除依据、文件哈希和时间排除逐题记录均在 `provenance/`。历史检索服务当时不可用，审计来自本地文件；不是宣称公开数据从未出现在模型训练中。32 道题类型分布偏向时间推理；没有足够未出现过的偏好和助手回答类题目，不补旧题冒充新题。

**LoCoMo 随机新题 200 道。** 数据来自 [Snap Research 官方 LoCoMo 仓库](https://github.com/snap-research/locomo)，固定提交 `3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376`。排除官方类别 5 的对抗题，因为本实验只度量正例引用覆盖；另外 13 道正例缺少证据或其证据编号无法精确解析，在检索前记录。剩余 1,527 道正例按下式排序，取前 200，不放回：

```text
seed = smm-new-retrieval-20261026-v1
SHA256(seed + NUL + "LoCoMo" + NUL + sample_id + NUL + question_index)
```

这 200 道题分布在全部 10 份人物历史中，共享历史的问题存在相关性，**不能当作 200 份独立人物历史**。保留原始官方类别编号，不采用第三方论文可能不同的类别名称映射。

两组分开统计，不混成一个总体百分比；旧 25 题只是已知开发参照，不加入新题分母。

## 保持不变的检索实现

- 原有 `SMMControlIndex`、`lexical_expression`、切片和 MiniLM 编码实现逐字复制，位于 `implementation/`，哈希在协议中。
- **BM25**：整段会话正文、SQLite FTS5 `unicode61`，原始问题提取至多 128 个去重词做 OR 匹配；没有新增分词、词干化、去停用词、关键词改写或查询扩展。按 BM25 分数排序，以来源 ID 打破并列。
- **向量**：`sentence-transformers/all-MiniLM-L6-v2`，384 维；原有按角色边界的 256 token / 48 重叠切片；编码器的 224 token / 32 重叠窗口取平均并 L2 归一化；一段会话取其最高切片相关分。没有新向量模型、摘要或提炼事实。
- 两路分别保留来源 Top10，评价 Top1～5；双路各取 Top N 再按来源 ID 去重，没有数值分数融合、AI 重排或 Agent 继续检索。
- 新检索之前，使用原 25 题和现有只读索引重放：**两路共 50 条 Top10 排名及分数全部与冻结基线一致，最大分数差 0**。这一步未重算原文向量。

本地源向量批量计算只优化计算安排。按相同窗口、池化和归一化规则与原逐条编码校验，误差门槛为 1e-6；实际差异及依赖版本、模型文件哈希、缓存命中、新编码数、耗时均保留在 `vectors/build.json`。原文与查询向量保存为 NumPy 文件，后续验证无需再次编码。

## 信息单位与时间

一段有日期的原始 session 对应一条完整对话记录。LongMemEval 保留原有 USER/ASSISTANT 角色；LoCoMo 保留两个说话人的姓名作为字面标题，没有把第二个人的陈述改成 AI 回答。

LongMemEval 只索引原始历史中不晚于问题时间的全部会话，不补无关人物、不截成固定 100 条，也不根据答案优先保留来源。LoCoMo 是对整份历史的回顾题，没有官方问题时间，明确将检索时钟设为该历史的最后一段时间，所有原 session 可见；这不是假定问题真实发生于该时刻。无时区数据统一用 UTC 作复现约定。

只索引原对话文字。LoCoMo 的生成 observations、session summaries、event summaries、图像、BLIP 描述与图片搜索词均不作为检索正文。`provenance/modality-audit.json` 记录标注轮次包含图像元数据的题，但没有据此事后删题。命中参考会话不保证文字足以回答依赖图片的问题。

## 指标与解释边界

主指标：**每题所有官方参考会话是否都被 Top N 包含**。只有所有来源同时入选才算成功，不是只命中其中一段。另报任意引用命中、引用次数召回、候选数、完整原文字符数、类别/来源数量/历史分组与逐题配对结果。

没有为新题事后制作“必要事实”标注，所以不要将本实验分数直接与旧实验 36 项手工必要信息分数比较；可以比较旧实验同口径的“全部官方参考对话取齐”结果。官方参考可能有重复旁证，漏掉一段不一定表示无法回答。没有执行模型回答，不能从来源覆盖率推算回答正确率。

如果题目标注了 5 段不同参考会话，单路 Top4 的容量就不够；这与排序错误不同。报告应同时检查参考会话数量造成的理论上限，并在参考数不超过 N 的问题中另看实际表现。双路各 Top N 的输入最多为 2N，不能把它直接当成相同输入成本下的单路 Top N。

## 复现与后续方法对比

先安装 NumPy；`score.py` 的覆盖率重放本身只依赖 Python 标准库，`--verify` 的独立向量数值复算需要 NumPy。

```bash
# 在仓库根目录：重算并逐字比较已保存的评分文件，不调用模型。
python3 -B experiments/smm-retrieval-generalization-001/score.py --check

# 独立从原文重建 BM25，并从已保存向量重算两路 Top10 排名。
python3 -B experiments/smm-retrieval-generalization-001/score.py --check --verify
```

`data/cases.json` 含评价信息。新的检索器只能使用问题、时钟、可见来源 ID 和原文；答案、官方引用、标注轮次、类型等不得进入检索计算。将新方法原生结果保存在新的目录，保留本轮首结果；保持同一批题、语料范围、引用标注、Top N 定义和评价脚本，才能作为方法对比。所有源文件都包括正文 SHA256 和精确角色/轮次坐标。

从零重新编码需要 FastEmbed、ONNX Runtime、Tokenizers 和对应模型资产，资源与版本详见 `vectors/build.json`。这与使用已封存向量复算不同，应单独记录新计算量。`prepare_data.py` 是一次性本机导入脚本，包含原审计目录路径；后续对比直接使用本目录已固定的数据，不依赖原机器。模型权重不随仓库分发。
