# 新问题上的 BM25 / 向量 Top N 验证

**SMM-RG001，232 道新题，固定当前检索实现，无新增回答或筛选模型调用。**

两组分别统计：LongMemEval 从未进入旧实验元数据且时间有效的剩余 32 题全部纳入；LoCoMo 按固定种子随机选取 200 题。协议、抽样与排除清单在首次检索前固定，运行后没有换题或调参数。完整方法见 [METHOD.md](METHOD.md)，冻结定义见 [protocol.json](protocol.json)。

**本页所有比例指全部官方参考对话取齐，不是答案正确率，也不是旧实验 36 项手工必要信息覆盖率。**旧 25 题同口径 BM25 Top4 为 25/25，向量 Top4 为 23/25，合并为 25/25。

## 记录与复算

- [原文诊断与标签疑点](case-audit.md)：真实互补、可替代旁证、主语及日期问题分开记录，不修改主分。
- [逐题结果](case-results.md)：每道题三种路线取齐所需的最小 N。
- [完整机器结果](results.json)：每个 N 的入选与遗漏来源、目标排名、配对。
- [分组汇总](summary.csv)：类别、历史、参考数量、任意命中、引用次数覆盖及输入量。
- [评分冻结记录](scoring-contract.json)：评分代码与输入协议在首次新检索前的绑定。
- `rankings/`：原实现首次返回的两路 Top10 分数与来源；`data/sources/`：完整原文与角色/轮次坐标。
- `vectors/`：原文块与查询向量、来源位置、模型资产哈希、软件版本、缓存/计算记录。

`verification.json` 记录真实搬迁重放：预先加载已安装的 NumPy/标准库后，禁止读取原 next-app 和原发布目录，禁止网络及子进程；三个拦截均实际触发，再在临时副本中通过独立评分核验。核验覆盖 1,748 段原文哈希、23,305 个切片位置、350 条标注原句与 464 条两路 Top10 排名。它证明数据与数值计算可重放，不等于官方答案都正确。

从仓库根目录运行：

```bash
python3 -B experiments/smm-retrieval-generalization-001/score.py --check --verify
```

独立重建两路排序需要 NumPy，不需要模型、密钥或网络。方法说明包含从零编码的范围与限制。

## 本次计算资源

首次本地构建用时约 1,353.4 秒（22.6 分钟），包括模型加载、切片、缓存检查和编码；新编码 22,065 个唯一原文块，精确复用旧缓存 708 块，另计算 232 个查询向量。这是新增材料的准备成本，不是一次检索的耗时。查询编码中位约 2.7 毫秒；已加载索引且复用查询向量时，两路联合搜索中位为 LongMemEval 约 4.3 毫秒、LoCoMo 约 3.5 毫秒。单机单次记录，没有网络、冷启动或实际回答模型，不当作 APP 端到端速度结论。**新增生成式模型调用、付费 API 请求均为 0。**

## 结论边界

这是本实现的新问题检索验证，不是新的官方排行榜。两组数据、任务类型、语料量和参考数量分布不同，不合并分母，也不把成绩变化单独归因于数据量。LoCoMo200 共享10份历史；只检索文本；没有新标注必要事实，没有回答试验。官方来源可能冗余，也可能没有穷尽所有可用旁证，所以取齐来源是可核验指标，未取齐则需要检查原文，不能自动等同于无法回答。所有局限与许可见 [METHOD.md](METHOD.md)。
