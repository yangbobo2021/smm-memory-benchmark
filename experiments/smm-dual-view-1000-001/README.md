# 全文 + 用户发言双视图，固定十条候选

同一原始问题、同一批每题 1000 段完整对话，分别对完整会话和仅 USER 发言建立 SQLite FTS5 `unicode61` BM25 索引。返回会话 ID 的固定顺序为：全文前 5、USER 前 5 去重、再按全文排名补足 10 条。原文未被改写，参考依据仍要从完整会话读取。

| 题组 | 全文 Top10 全部参考 | USER-only Top10 全部参考 | 双视图十条全部参考 | 双视图十条至少一条参考 |
|---|---:|---:|---:|---:|
| P25 | 19/25 | 22/25 | 21/25 | 25/25 |
| L32 | 16/32 | 16/32 | 17/32 | 25/32 |
| 合计 | 35/57 | 38/57 | 38/57 | 50/57 |

相对全文 Top10，双视图救回 P07、P20、L021，未回退；Top5 仍是全文前五，故 Top5 取齐不变。这个方法在看过官方 M 的互补结果后提出，当前混合1000数据此前也用于若干诊断，不是盲测。十条只是候选源是否含官方参考，不是模型是否识别、读取、回答正确。

协议先于本实验排名冻结于 `protocol.json`。`run.py` 输出57题逐项参考位置、两个视图 Top10、合成候选和索引/查询耗时；`verify.py` 从源文件哈希重建两个索引并逐题数值重放，57/57通过。仅 USER 索引构建中位约13.4 ms、查询约1.4 ms，均为本机临时索引运行时间。

更完整的规模对比、官方 M 转移结果、逐例失败和实施边界见 [官方 M 复核报告](../smm-official-m-500-001/REPORT.md)。
