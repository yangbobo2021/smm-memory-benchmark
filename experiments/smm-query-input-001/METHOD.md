# SMM-QI001：两路独立查询输入对照

问题：在索引、模型和候选预算不变时，为 BM25 与向量检索分别设计输入，能否改善对原始对话的召回？

## 先检查输入，再运行检索

257 个问题沿用原 25 题、后续 LongMemEval 32 题、LoCoMo 200 题，三组分别报告。这些是已用题，不是新盲测。作者曾接触本项目历史分析，不能宣称完全未见过答案。本次改写阶段只列出原问题，未打开参考答案、参考原文或遗漏列表来决定用词；此前讨论过的例子仍有历史知情限制。

`authored-inputs.tsv` 为 Codex 在本任务中逐题编写的输入，不是规则批量删词，也不是另行付费调用生成模型。每题严格只有一个 BM25 输入和一个向量输入；不拆子查询，不使用多轮补查，不根据结果挑选改写或重跑。

BM25 输入保留对象、事件、区分性词汇，并适量展开常见词形与等价词。例如 `bake baked baking`。不加入答案中的人名、地点、数值、具体对象或假设答案。

向量输入使用简短自然语言，保留问题的语义范围，尤其是人物、时间、当前/最初/过去、已发生/计划、否定、集合计数、先后关系及推断性质。简单问题不必强行复杂化。

作者在检索前逐题检查信息是否充分、有没有缩小集合或添加已知答案。检查能够确认的是表达保真与输入合理性，不能证明这就是最优输入，也不是外部独立评审。预检修正三处过度扩展：Ibotta 的“下载”不等于“开始使用”；“family give”不能预设为支持或礼物；“states”不额外添加国家假设。它们在任何新查询检索前修正。

## 保持不变的部分

- BM25：原 SQLite FTS5 unicode61、原始全文、OR 连接去重词，默认公式、同样的时间可见性；不新增 must/boost/not 或日期硬过滤。
- 向量：原 MiniLM-L6-v2、原切片和全部文档向量；切片相似度取每段对话的最大值；无模型替换、重切片或新文档编码。
- 每路每题只运行一次输入；不追加原问题检索结果来兜底。
- 各自 TopN 合并为完整并集，按对话 ID 去重，不再截成 N 条。
- 相对时间约束保留在问题与向量输入中；原时钟继续控制未来资料可见性。当前匹配器不会把时间文字转换为严格日期过滤，因此输入保真不等于时间约束已被引擎执行。

## 冻结评估

报告单路原始/改写 Top1–5、两路并集 Top1–5。预先注册四种并集：原BM25+原向量、改写BM25+原向量、原BM25+改写向量、改写BM25+改写向量。中间两种用于分辨哪一路带来变化，不按成绩挑选最佳配置作为主结果。主结果是原/原与改/改在相同 N 下的配对比较。

主指标为全部官方参考对话取齐；同时报告至少一条参考命中、参考段次覆盖、平均候选数、逐题增益/回退。原25题另报已有必要证据口径；另两组没有同等必要证据标注，不虚构等同口径。不调用回答器或模型裁判，不能报告回答正确率。

旧背景引用、歧义和替代证据限制继续保留：L004/L015，C088/C172、C198等，不改gold。严格引用提升需要结合原句判断，不能自动视为答案改善。

本次是输入设计诊断。即使有提升，也不能证明运行时 Agent 能稳定生成同样质量的输入；即使无提升，也不能证明不存在更好的输入。
