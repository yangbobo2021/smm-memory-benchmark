“原题历史范围”仅是数据集问题特定历史的**身份范围上界诊断**，不能在真实检索时靠答案或官方参考推导出来。真实应用若有登录用户／知识空间 ID，可在写入和查询时用稳定 ID 作范围约束。姓名说话人子集则是用户所提人物提取的简化版，不包含实体消歧；本8题里它碰巧与原题历史范围得到相同的总数，但逐题来源构成不同，不能视为等价。

这组受选案例里，8题均明确写出主人公姓名，原题历史会话也都有对应说话人；现实文档中的第三方人物可能只被提及而不发言。8题是为机制诊断选的已知例，不是随机抽样。先前关键词输入由研究者编写并对基准有历史知情，虽然早于1000段压力测试，也不能当成真实 Agent 自动生成查询的成功率。

## 对架构的判断

可以在写入时保存**涉及人物**，但应区分 `speaker`、`mentioned_person` 和稳定的 `person_id`；名字字符串本身不够。C183 的 1000 段里有92段说话人叫 John，只有29段属于该题原有历史；单用“John”仍把多个不同 John 混在一起。首先该用用户／租户／知识空间 ID 划定有权限的历史；在范围内，如果 Agent 明确知道实体身份，再利用 person_id 缩小候选，同时保留仅提及该人物的文档入口。最后仍需用事件、时间和要点排序。对第一人称、没有人名的 P20/L028，人物提取无法从问题中给出目标身份，登录用户范围才是关键；在原题历史范围，它们的参考分别排第1、第5，混合1000段后降至第23、第115。

因此这个小试验支持**身份范围＋可调查询输入**的方向，不能证明“给每段提取人名就足以解决1000段检索”。它也提示先修正测试语料的用户归属：跨用户混库造成的退化不该算成同一用户自然积累的退化。剩下 C157/C051 这样的同范围多证据问题，还需要继续研究事件与事实线索如何在 Top5 中排得更前。
