# 为什么 LongMemEval 在 1000 段时下降更多？

这是在主实验结果固定后做的**事后机制诊断**，不改变主实验的 BM25、语料、问题或官方参考标注。使用同一 57 道 LongMemEval 问题及同一每题 1000 段来源，仅将索引正文分别换成 USER 发言和 ASSISTANT 回复；查询仍是原问题、同一 `unicode61` BM25。源码 [diagnose_roles.py](diagnose_roles.py)、逐题位置和汇总 [role-diagnostic.json](role-diagnostic.json)。这不是预先冻结的优选方案评估。

| 题组 | 全文 Top5 / Top10 取齐 | 只索引 USER Top5 / Top10 | 只索引 ASSISTANT Top5 / Top10 |
|---|---:|---:|---:|
| P25 | 18/25、19/25 | 18/25、22/25 | 18/25、18/25 |
| L32 | 15/32、16/32 | 14/32、16/32 | 11/32、15/32 |

2675 段去重 LongMemEval 会话中，ASSISTANT 文本占 USER+ASSISTANT 字符数的中位数约 **89.3%**。在 P25 中，去掉 ASSISTANT 回复使 2 道原本漏的 Top5 题恢复，但同时让另 2 道原本取齐的题漏检；L32 恢复 1 道、损失 2 道。因此“AI 回复带来词法噪声”是真实机制之一，**只删回复并不能整体修复 Top5**。Top10 上 P25 从 19 升至 22，L32 维持 16，表明某些较深排名确有改善。

逐题对照更清楚：

- **P20** 问何时停止查看工作邮件。正确来源原本排第 1，扩至 1000 段后全文排第 23；只索引 USER 排第 2，只索引 ASSISTANT 排第 380。全文第一名的干扰对话，USER 主要讨论流程挖掘，ASSISTANT 回复却碰巧出现 `checking`、`emails`、`time` 等词。这里 AI 回复确实是主要噪声。
- **L028** 问上周二午餐见了谁。正确来源全文排第 115、只索引 USER 排第 15、只索引 ASSISTANT 排第 535。回复干扰很大，但只用 USER 仍进不了 Top10：别的 USER 发言也直接包含 `lunch`、`Tuesday` 等问句词，而正确来源里的关键事件说法并未直接命中所有这些词。
- **L004** 问两周前艺术活动的地点。两条官方参考全文排第 38、28；只索引 USER 排第 54、120；只索引 ASSISTANT 排第 16、8。此题反过来说明回复中也可能保留有用的线索，删回复会恶化。

语料构成本身也是关键：P25/L32 补入的是同一 LongMemEval 系列的其他会话，所有 57 题的扩充 Top10 平均有 **8.4 段**来自原题之外。它们大量涉及第一人称日常安排、工作、饮食、活动，常与没有专有名称的原问题共享词。C200 则使用所有 272 段 LoCoMo 加 728 段 Conversation Chronicles；后者虽是完整对话，但在 200 题的 **2000 个 Top10 席位中只占 99 个**。LoCoMo 题往往带人物名称，而外部语料不涉及这些人物；所以 C200 看起来稳定，不能解释成 BM25 对所有类型的 1000 段都抗干扰。

结论限于这次候选池与原问题：**主要问题是词法相似的竞争来源增多，加上长回复的泛化词汇，二者共同改变排名。** ASSISTANT 文本很长，但其占比本身不是错误率；“删掉 AI 回复”没有得到稳定收益。不同人物历史混在一个检索池、相对时间没有按查询时钟过滤，也会加剧误匹配。本诊断不能推断在真实单用户时序库、改写查询或其他检索策略上的效果。
