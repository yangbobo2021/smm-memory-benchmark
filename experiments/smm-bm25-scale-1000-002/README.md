# 原 BM25 在每题 1000 段完整对话中的检索验证

本实验保留先前的 **257 道问题、原始问题文本、官方参考来源、整段对话 BM25 实现**，只扩大候选语料。比较每题原有的 19–62 段来源与扩充后的 **1000 段不同完整对话**。每段新增干扰对话都来自已经发布的数据集；本实验没有生成或拼接虚构对话，也没有向量、查询改写、重排或模型调用。协议和每题语料清单在打分前写入 [protocol.json](protocol.json)。

## 语料怎样组成

| 题组 | 题数 | 补充来源 | 1000 段的关系 |
|---|---:|---|---|
| P25、L32 | 25、32 | [LongMemEval](https://github.com/xiaowu0162/longmemeval) 的其他完整会话 | 每题保留原有来源，再按冻结哈希顺序补足同系列会话；不同题的补充集合可不同 |
| C200 | 200 | 全部 272 段已发布 [LoCoMo](https://github.com/snap-research/locomo) 会话，加 728 段 [Conversation Chronicles](https://huggingface.co/datasets/jihyoung/ConversationChronicles) 原生完整会话 | 全部 200 题共用相同的 1000 段 |

LoCoMo 发布语料本身只有 272 段会话，因此 C200 无法只用该数据集补至 1000。补入的 Conversation Chronicles 来自固定 `test` 版本 `9639b3552594a612ceafa76238a34f0f6eeaa207`：按源文件顺序取满足至少 15 轮、序列化后至少 1800 字符的前 728 段原生会话；中位 18 轮、2002 字符。原 LoCoMo 会话中位 2670 字符，两者长度仍不完全一致。其[论文](https://aclanthology.org/2023.emnlp-main.838/)说明这些对话由大模型生成，**它们是公开数据集中已经存在的对话，不是真实人类用户记录**。只保留原始 speaker/utterance，未把数据集自带的摘要加入索引。原文与来源坐标在 [data/conversationchronicles-selected728.jsonl](data/conversationchronicles-selected728.jsonl)。

每题 1000 段均有不同正文哈希，原题的所有来源都保留，问题和参考标注不变。LongMemEval 的跨题会话可能来自不同人物或不同时间切片；Conversation Chronicles 也不是 LoCoMo 人物的真实后续。因此这是**语料规模与词法干扰压力测试**，并非某一个用户按时间累积 1000 条记忆的因果模拟。

## 结果

“取齐”指 TopN 包含该题全部**官方参考对话 ID**；“至少一条”指包含至少一个官方参考。两者都是来源命中指标，不等于 Agent 可回答、事实充分或最终答案正确。分组不合并为一个泛化成功率。

| 题组 | 原 Top5 取齐 | 1000 段 Top5 取齐 | 原 Top10 取齐 | 1000 段 Top10 取齐 | 1000 段 Top5 / Top10 至少一条 |
|---|---:|---:|---:|---:|---:|
| P25 | 25/25 | **18/25** | 25/25 | **19/25** | 24/25 / 24/25 |
| L32 | 20/32 | **15/32** | 22/32 | **16/32** | 22/32 / 24/32 |
| C200 | 156/200 | **156/200** | 167/200 | **173/200** | 177/200 / 188/200 |
| 合计，描述性 | 201/257 | **189/257** | 214/257 | **208/257** | 223/257 / 236/257 |

以 1000 段结果看，P25 的 Top5/Top10 取齐率为 72%/76%，L32 为 46.9%/50%，C200 为 78%/86.5%。C200 的 Top5 总数不变，实际上有 **6 题由命中变为漏检，另 6 题由漏检变为命中**；Top10 有 2 题退化、8 题改善。增加语料改变整个索引的词频与 IDF，所以相关文档的 BM25 相对顺序可能双向变化，不能只看净总数。

具体反例：P20 问停止查看工作邮件的时间，原参考排第 1，在 1000 段时跌到第 23；L028 问上周二午餐见了谁，参考从第 5 跌到第 115。它们表明仅用原始问句的词法重合，遇到大量相似主题的其他完整对话，不能稳定保住目标。C005 的参考从第 4 跌到第 6；C094 的参考反而从第 20 升至第 4，表明 C200 总数不变并非逐题不变。[每题原始记录](results/)保留参考排名，[Top10 排名轨迹](top10.jsonl)保留来源 ID 与分数。

这组数据**不支持**“BM25 在 1000 段时 Top5 通常取齐 90%，Top10 接近 99%”的判断。它也不能单独判定是否必须引入向量或语义关系，因为本轮只改变了语料规模，未比较其他方案；部分官方参考可能是冗余证据，未取齐官方 ID 不必然等于答案信息缺失。

## 复现与审计

Python 3.11+ 标准库、SQLite FTS5。`prepare.py` 是冻结前的一次性建协议脚本，已有协议时会拒绝覆盖。`score.py` 对每题分别建原库和扩充库，使用归档的 `lexical_expression(question)`、`unicode61`、整段正文和原始 BM25 计分；逐题先复放原 Top10 并与归档结果一致，才记录扩充排名。`verify.py` 离线重算全部 257 题的两种排名并校验来源哈希、1000 段正文去重和 C200 共享语料。`top10.py` 单独输出排名轨迹；不改变冻结打分。

```bash
python3 -B experiments/smm-bm25-scale-1000-002/verify.py
```

离线重放结果：257/257 题通过。完整汇总在 [summary.json](summary.json)。本轮的 1000 段内存建库中位约 19.3 ms，已建库后的 BM25 查询中位约 1.5 ms；这是单机进程内测量，**不是线上服务、网络或 Agent 的端到端延迟**。
