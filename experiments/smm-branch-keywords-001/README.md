# 对话分支关键词索引实验（SMM-BR001）

本实验固定 LoCoMo 的 200 道原问题及 272 段完整对话。GPT-6 Luna high 仅阅读原始对话，
为不同讨论分支提取关键词；检索时仍把整段对话作为候选单位。主要指标只统计预先明确标注的 178 题，
其余 22 题有依赖歧义，未混入主分母。测试过的题和来源不能视为全新盲测。

## 提取和成本

- 272 段对话产生 962 个分支，平均 3.54 个/段。
- 模型调用耗时合计 2791.5 秒，平均 10.26 秒/段（并行时墙钟时间更短）。
- 输入/输出 token 合计 2946524/111700。
- 轮次引用覆盖率平均 96.2%；这只能说明轮次被标到，不能证明关键词完整。
- 机械格式裁定 8 段，原始响应及裁定均保留。
- 向量编码含模型加载和整段对照索引耗时 48.7 秒；200 题排名计算 0.5 秒。

## 结果判断与真实例子

**这组数据不支持用分支关键词替换整段原文索引。**使用同一个归一化问题，分支 BM25 Top5 比整段 BM25 少取齐 17 题；逐题是 9 题新增、26 题回退。Top10 少 13 题；分支向量 Top5 也从 106/178 变为 104/178。分支提取确实建立了一些更聚焦的入口，但压缩后的词表丢失了问题中用于识别正确对话的上下文。

- **有帮助的情况：C172。**“James 去加拿大计划待几天？”的正确对话有独立的“加拿大／多伦多／温哥华旅行”分支。整段 BM25 排第 15，分支 BM25 排第 1。对话里还有游戏、运动、阅读等内容，分支让旅行主题不再被整段文字稀释。
- **丢失人物锚点：C004。**原问题问 Dave 认为汽车修复最难的部分。正确对话原文同时有 “Dave”“toughest”“car restoration”，整段 BM25 排第 1。提取的汽车分支保留了“修复、耐心、细节”，却没保留 Dave，分支 BM25 降到第 11。
- **丢失事件限定：C008、C023。**去 Phuket 的分支保留了目的地，却丢掉原文中的“伴侣、几周”等限定，正确对话从第 2 降到第 23。问题中的“九月”来自来源时间，并未作为原文提供给提取模型。另一个问题以“妈妈、Nintendo Wii”寻找最喜欢玩的游戏；分支保存了游戏名《Monster Hunter: World》，却没保存 Wii 这个查找线索，正确对话从第 3 降到第 11。
- **词形和关系都可能断裂：C067、C165。**“roadtrip 之后何时 hike”的原文含连写 `roadtrip`，分支写成 `road trip` 且未保留具体 hike 事件，BM25 不再匹配正确对话。询问 Tim 在特定日期向 John 推荐哪本书时，分支列出了《Dune》等书名，却省略人物、推荐动作和日期，BM25 同样没有召回该对话。

额外的探索性检查：归一化整段 BM25 Top5 与分支 BM25 Top5 合并去重，平均展示 7.70 段，取齐 161/178；单用归一化整段 BM25 Top8 取齐 162/178。分支路线在本组没有表现出足以抵消提取成本的净增益。此合并检查没有在原始主协议中冻结，不作为主结论依据。

这也说明“轮次被分支标到”不等于“该轮所有未来可检索的表达都进入关键词列表”。分支可用于导航和结果展示，但原文仍是更可靠的基础检索入口。若继续研究，应测试保留原句片段或实体／时间／关系锚点的分支索引，并在新样本上验证；当前结果不支持直接上线替换。

## 解释边界

这些数字衡量候选对话是否包含预先标注的必需来源，不衡量 Agent 是否选对证据或答对。
LoCoMo 的 200 道题来自少量共享历史，题目之间不独立；仅凭本组差额不能宣布泛化优势。
若分支索引增加漏检，应检查关键词是否丢了旁支事实、Porter 词形与关键词是否错位，以及每段取最高分是否偏向多分支对话。
所有请求、模型输出、来源绑定、逐题排名和评分脚本均在本目录。

## 复核与复算

仓库根目录下运行 `python3 -B experiments/smm-branch-keywords-001/audit.py` 可复核 272 次 Luna high 调用与原文绑定；运行 `python3 -B experiments/smm-branch-keywords-001/verify.py` 可在不下载模型、不调用服务的情况下重放 178 题的覆盖统计。`rankings.json` 保留每题、每方法的完整来源排序，`results/` 保留逐段对话的模型实际输入、输出、用量和耗时。`adjudications/` 单独保留 8 条机械格式裁定，未覆盖原始响应。

从头重新计算向量排名需要 Python 3.12+、`fastembed==0.9.0`、`numpy` 和 MiniLM 模型文件；可用 `SMM_MINILM_CACHE` 指向已有 FastEmbed 缓存后运行 `score.py`。模型提取脚本 `extract.py` 需要已授权的 Codex 订阅环境，重跑会消耗模型额度；已经归档的输出足够完成离线统计复核。
